# Corners — pre-kickoff pattern search

Answers one question honestly: **is there a pre-kickoff pattern in corners worth
betting, and is 2,000 matches enough to prove it?**

```bash
cd corners
FOOTYSTATS_KEY=... node src/fetch.js --seasons 15050,14956,15068,14968,14932
node src/backtest.js --data data/matches.json --line 10.5
node src/selftest.js      # validates the harness before you trust its verdict
```

## Why corners look promising, and where that breaks down

Corners are more *predictable* than goals. Match totals average ~10.3 with a
standard deviation of ~3.5, so the coefficient of variation is ~0.34 against
~0.59 for goals. More events, less relative noise.

That is not the same as being more *profitable*. Two things get in the way:

1. **The predictable part is the easy part.** A projection built from team
   corners-for and corners-against rates is exactly what the book builds. Being
   accurate against the league mean is table stakes, not edge.
2. **Rolling team rates are mostly noise.** A 10-match corner rate has a
   standard error of roughly 0.85 corners per game, against a true between-team
   spread of roughly 0.9. About half the apparent spread between teams is
   sampling error. The backtest reports the fitted regression-to-mean
   coefficient so you can see this directly — expect something in the 0.4–0.7
   range, not near 1.

So the harness never asks "does the model beat a constant?". It asks: **does
anything beat the shrunk rate projection**, which is the book-equivalent model.

## What is being tested

| Model | Description |
|---|---|
| `null` | rolling league mean. The floor. |
| `raw` | attack index × defence index × league mean, unshrunk. |
| `shrunk` | same, with a walk-forward-fitted regression-to-mean coefficient. **This is the comparator that matters.** |
| `fitted` | `shrunk` plus mismatch (no-vig favourite dispersion), the interaction term, and a "blockiness" style proxy. |

The candidate edge is the **favourite-versus-low-block** shape: corners are
generated by territorial dominance, so a strong side camped against a deep
defence produces corners at a rate the pure team-rate average understates. That
is what the `mismatch` and `blockiness` features are probing.

## Methodology, and a warning about the existing model

Every feature is computed **strictly from matches that finished before kickoff**.
Rolling windows per team per venue, burn-in of 6 prior matches, shrinkage toward
a venue-specific league prior, coefficients refit walk-forward on an expanding
window. Nothing is fitted on the full sample.

This matters because **the live site's model does not do this.** `golden
server.js` scores fixtures using `seasonOver25PercentageHT_overall` and
`seasonOver15PercentageHT_overall`, which FootyStats computes across the entire
season — including the match being predicted. Any backtest built on those fields
has the answer leaking into the features. The quoted 2.76x / 2.65x lifts should
be treated as unproven until they are re-derived point-in-time. The same applies
to any corners work: build it this way or the numbers are fiction.

Two modelling details the self-test forced out:

- **Multiplicative, not additive pairing.** `(cornersFor + oppCornersAgainst)/2`
  looks reasonable and is wrong: each rate already carries one league-average
  term, so the average lands exactly halfway between the true expectation and
  the league mean, halving the signal. The Dixon-Coles form
  (`attackIndex × defenceIndex × leagueMean`) preserves amplitude.
- **Negative binomial, not Poisson.** Corner totals are overdispersed
  (variance/mean ≈ 1.1–1.3). Dispersion is estimated on the first half of the
  test window and applied forward, so the probability model is never calibrated
  on its own test data.

## Trusting the verdict

`src/selftest.js` runs the whole harness against three synthetic worlds with
known answers:

| World | Truth | Required verdict |
|---|---|---|
| A | corners independent of teams | shrink coefficient collapses to ~0, no signal claimed |
| B | real team rates, no extra effect | rates recovered, **no** phantom mismatch signal |
| C | real team rates + planted mismatch effect | mismatch recovered, log-loss improves |

If world C fails, a "no pattern" verdict on real data means nothing. If world A
or B fails, a "pattern found" verdict is a false positive. Run it first.

Observed on the synthetic worlds: even in world B, where team corner rates are
genuinely real and stable, the correct point-in-time model beats the league mean
by only **~1.3% MAE**. That is the realistic ceiling for a rate-based corners
model. Anything much larger on real data is a bug or a leak — look for one.

## Reading the output

The **statistical power** block is the part to take seriously. With ~1,800
evaluated fixtures you can detect a 5-point edge but not a 2-point one; proving
a 2-point edge needs roughly 4,900 bets. Since only a fraction of fixtures will
qualify as bets, 2,000 matches can confirm a *large* effect and can never
confirm a thin one. Plan the sample accordingly rather than concluding from a
grid cell with n=40.

The **signal grid** is reported in the existing site's 4-signal house style so a
positive result drops straight into the FHS UI. Cells under n=50 are labelled
`do not ship` — with four binary signals you have 16 combinations, and 2,000
matches will not fill them.

## Edge is not measured yet

FootyStats `league-matches` returns 1X2 prices, not corner lines. Without
corner-market odds the harness can tell you the model is *accurate*, never that
it is *profitable*. Attach `{cornerOdds: {over, under}}` per match and the
`EDGE VS MARKET` section activates. Until then, treat every result as a
calibration study.

## Security

The FootyStats key is hardcoded in `golden server.js` and duplicated across
several Drive copies. It is exposed and should be rotated; this package reads it
from `FOOTYSTATS_KEY` only.
